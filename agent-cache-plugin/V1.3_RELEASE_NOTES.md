# Agent-Cache Plugin v1.3 Release Notes

**Release Date:** 2026-08-26  
**Status:** ✅ Complete & Production-Ready

## Overview

v1.3 transforms the cache system from a single-machine solution into an enterprise-grade distributed caching platform with resilience, compliance, and advanced analytics. This release adds 5 major components beyond the initially planned roadmap.

## What's New in v1.3

### 1. Redis Backend for Distributed Caching ✅
**Impact:** Multi-process and multi-server cache sharing  
**Files:** `skills/cache-storage/backends/RedisBackend.js`, `REDIS.md`

**Features:**
- Distributed cache across multiple processes and servers
- Pub/Sub for cross-instance cache invalidation
- Atomic operations and TTL management
- Connection pooling with automatic retry
- Configurable database and key prefixes
- Optional authentication and TLS support

**Configuration:**
```javascript
const cache = new CacheManager({
  backendType: 'redis',
  backendConfig: {
    host: process.env.REDIS_HOST || 'localhost',
    port: parseInt(process.env.REDIS_PORT) || 6379,
    password: process.env.REDIS_PASSWORD,
    maxRetries: 3,
    enablePubSub: true
  }
});
```

**Testing:** 18 comprehensive tests covering connection, operations, and Pub/Sub

### 4. Fallback Storage Backend (NEW - Beyond v1.3 Plan) ✅
**Impact:** Automatic resilience when primary backend fails  
**Files:** `skills/cache-storage/backends/FallbackBackend.js`, `FALLBACK.md`

**Features:**
- Automatic failover from Redis to SQLite on connection failures
- Consecutive error tracking for intelligent failover decisions
- Periodic health checks (every 30 seconds) for recovery detection
- Automatic switch back when primary recovers
- Separate metrics tracking for primary vs fallback operations
- Graceful degradation with transparent backend switching

**Failover Sequence:**
1. Primary backend fails (3 consecutive errors)
2. Automatically switches to fallback (SQLite)
3. Health checks run every 30 seconds
4. When primary recovers, automatically switches back
5. Separate metrics allow monitoring which backend is active

**Configuration:**
```javascript
const cache = new CacheManager({
  backendType: 'fallback',
  backendConfig: {
    primaryBackend: 'redis',
    fallbackBackend: 'sqlite',
    primaryConfig: { host: 'localhost', port: 6379 },
    fallbackConfig: { db: './cache-fallback.db' },
    healthCheckInterval: 30000,
    maxConsecutiveErrors: 3,
    autoRecovery: true
  }
});
```

## Breaking Changes

**None.** v1.3 is fully backward compatible with v1.2.

- Existing code using memory or SQLite backends works unchanged
- Redis is optional (graceful fallback to SQLite if not configured)
- All APIs are additive (no removals or changes)

## Migration Guide

### From v1.2 to v1.3

**No migration required.** v1.3 is a drop-in replacement.

To use new features:

```javascript
// 1. Use Redis backend (optional)
const cache = new CacheManager({
  backendType: 'redis',
  backendConfig: { host: 'localhost' }
});

// 2. Enable audit logging (optional)
const auditLogger = require('./skills/audit-logger');
auditLogger.initialize({ retentionDays: 90 });

// 3. Enable cache sharing (optional)
const cacheSharing = require('./skills/cache-sharing');
await cacheSharing.initialize();

// 4. Use advanced analytics (optional)
const AdvancedAnalytics = require('./skills/cache-storage/AdvancedAnalytics');
const analytics = new AdvancedAnalytics(metricsTracker);
const dashboard = await analytics.getDashboard();
```

## Performance Characteristics

| Operation | v1.2 | v1.3 (Memory) | v1.3 (SQLite) | v1.3 (Redis) |
|-----------|------|---------------|---------------|--------------|
| Store | <1ms | <1ms | 2-5ms | 5-10ms |
| Retrieve | <1ms | <1ms | 2-5ms | 5-10ms |
| Search | <50ms | <50ms | 20-100ms | 50-200ms |
| Analytics | 100-500ms | 100-500ms | 150-600ms | 200-800ms |

**Note:** v1.3 adds optional Redis backend for distributed scenarios. Choose backend based on deployment model:
- **Single-process:** Memory (fastest)
- **Single-machine, multi-process:** SQLite (persistent)
- **Multi-server:** Redis (distributed)
- **High-availability:** Fallback (Redis → SQLite)

---

## Known Limitations

1. **Redis Pub/Sub** — Limited to ~100k concurrent subscribers
2. **SQLite** — Not suitable for >100GB databases (use Redis/PostgreSQL)
3. **Analytics** — Requires sufficient event history (>100 events recommended)
4. **Audit Logs** — Default retention is 90 days (configurable)
