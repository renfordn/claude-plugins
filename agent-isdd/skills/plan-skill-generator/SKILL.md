# Plan Skill Generator

**Purpose:** Fast discovery phase that outputs a reusable JSON plan for running a project.

Instead of a monolithic "figure out and build everything" process, this skill does the research upfront. It identifies the project type, build system, launch method, and potential gotchas—then outputs a structured plan that other skills or agents can use.

**Use this when:**
- You need a lightweight analysis of how to run a project
- You want to review the plan before committing to building a full skill
- You'll be creating the skill multiple times or want to iterate on the plan
- You need to understand a project's structure without building a driver

**Output:** JSON plan file (`project-plan.json`) with discovery findings.

## Quick Start

```bash
cd /path/to/project
claude plan-skill-generator
```

This analyzes the project and writes `project-plan.json` to stdout and the current directory.

## What Gets Analyzed

The discovery process examines:

1. **Project manifest** (package.json, go.mod, Cargo.toml, pyproject.toml, etc.)
2. **Build configuration** (Dockerfile, Makefile, build scripts, CI configs)
3. **Launch patterns** (dev server entries, bin scripts, executable entry points)
4. **Testing setup** (test runners, test command patterns)
5. **Common entry points** (.github/workflows, package.json scripts, Makefile targets)
6. **Dependencies** (UI frameworks, web servers, CLI libraries)

## Output Format

The plan is a JSON document (see `references/plan_schema.json`):

```json
{
  "unit_path": ".",
  "unit_type": "web-app|cli|library|desktop|server|monorepo",
  "detected_technologies": ["react", "vite", "node"],
  "build_system": "npm|cargo|go|python|make",
  "test_framework": "vitest|pytest|jest|cargo test",
  "launch_method": "dev-server|binary|script|python|import",
  "device_type": "headless|gui|tty",
  "key_findings": [
    "web app with react + vite",
    "runs on port 5173",
    "build output in dist/"
  ],
  "potential_issues": [
    "requires npm install",
    "GPU access not available in container"
  ],
  "recommended_driver_pattern": "playwright|cli|tmux|library",
  "confidence_level": 0.85,
  "discovery_metadata": {
    "files_scanned": 15,
    "patterns_matched": 10,
    "discovery_time_ms": 3421
  }
}
```

## Edge Cases & Gotchas

- **Monorepo detection:** If `apps/` or `packages/` dirs exist, the skill asks which unit to plan for
- **Ambiguous build systems:** When multiple build tools exist, confidence_level reflects uncertainty
- **Missing manifests:** Legacy projects without package.json or equivalent — detection falls back to file-scanning heuristics
- **Feature gates:** If docs mention "requires paid feature," the discovery notes it but doesn't probe for credentials

## Next Steps

Once you have the plan:

1. **Review it** — Check that unit_type, build_system, and launch_method are correct
2. **Modify if needed** — Edit the JSON directly to adjust findings
3. **Pass to run-skill-generator-execute** — Use the plan to build the full skill:
   ```bash
   claude run-skill-generator-execute --plan project-plan.json
   ```

The execute skill will skip discovery and go straight to building the driver and SKILL.md.

## Token Efficiency

- **plan-skill-generator alone:** 3-5k tokens

- **vs. monolithic (discovery + execution):** 12-20k tokens
- **Savings for iterative workflows:** 50-60% per execution after first plan

## Troubleshooting

**"Could not determine project type"**
- The project structure didn't match known patterns. Review the key_findings and potential_issues — they may indicate why.
- Manually set `unit_type` in the JSON and re-run execute with `--plan`.

**"Multiple build systems detected"**
- The confidence_level will be lower. The skill guesses based on frequency/priority, but review the findings to confirm which is primary.

**"No launch method found"**
- This often means the project is a library or has non-standard launch. Check `recommended_driver_pattern` — it may suggest "library" (import-and-call) or "script" (run with arguments).
