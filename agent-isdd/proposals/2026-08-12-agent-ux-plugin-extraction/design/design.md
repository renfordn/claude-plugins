# Design: agent-ux plugin extraction

## Status

- Phase: Design
- State: Draft
- Last Updated: 2026-08-12

## Design Summary

Extract `agent-isdd/agents/ux-agent.md` and `references/ux-conventions.md` into a new plugin,
`agent-ux`, near-verbatim, plus a new `INTEROP.md` that defines a versioned, minimal **event
envelope** as the only thing callers pass across the plugin boundary. No new rendering capability
is added — this is packaging plus a contract, deliberately, so the extraction itself carries zero
UX-behavior risk. The contract's central design decision is **pull over push**: callers hand
`agent-ux` a path plus a small delta, and `agent-ux` reads further (via its existing `Read` tool)
only if and when it decides an action is warranted — never the reverse.

## Research Basis

- Wide-pass candidates: `agent-isdd/agents/ux-agent.md`, `references/ux-conventions.md`,
  `INTEROP.md` (as the pattern to mirror), every skill that currently invokes `ux-agent`
  (`spec-driven-development`, `workflow-manager`, `requirements-agent`, `design-author`,
  `tdd-planner`).
- Deep-pass findings: `ux-agent.md`'s four action families (breadcrumb, spec canvas, review
  dashboard, chapter markers, out-of-scope flags) and their existing per-action gating thresholds
  are the load-bearing constraint on the new envelope shape — the extraction must reproduce each
  threshold exactly, not just the action names.
- Memory brief used: none — this is a proposal authored directly in conversation, not run through
  `agent-nelly:nelly-orchestrator`.
- **Not done**: no equivalent research pass exists against `agent-tdd`'s or `code-reviewer`'s own
  repos (out of this session's access). The `caller`-keyed rules below (e.g. TDD-stage exclusion)
  are carried over from what `agent-isdd`'s `ux-agent.md` already documents about `agent-tdd`,
  not independently confirmed with `agent-tdd`'s maintainers.

## Scope Mapping To Requirements

- Requirement: soft dependency only
  - Design Response: `agent-ux` unavailability handling is defined once in `agent-ux`'s own
    `INTEROP.md`; each caller's `INTEROP.md` references it rather than restating it (see Risks).
- Requirement: per-event payload must not exceed today's baseline
  - Design Response: pull-over-push envelope design (below); per-`event_type` size budget stated
    as a Validation Strategy gate.
- Requirement: preserve checkpoint-only gating
  - Design Response: gating thresholds ported unchanged from `ux-agent.md` into the new agent
    definition; caller-side callsites unchanged in when they delegate, only in who they delegate
    to.
- Requirement: cheapest capable model
  - Design Response: `agent-ux:ux-agent` ships pinned to `haiku`, same as today.
- Requirement: rendering-only, no workflow logic
  - Design Response: envelope carries only rendering-relevant fields (below) — no phase-decision
    fields, no checklist state.

## Architecture Or Code Touchpoints

- New plugin `agent-ux` (separate repo): `agents/ux-agent.md` (ported), `references/ux-conventions.md`
  (ported), `INTEROP.md` (new — the event contract), `.claude-plugin/plugin.json`, `CHANGELOG.md`.
- `agent-isdd` (this repo): remove `agents/ux-agent.md` and its local `references/ux-conventions.md`
  ownership once `agent-ux` ships; update `spec-driven-development`, `workflow-manager`,
  `requirements-agent`, `design-author`, `tdd-planner` to delegate to `agent-ux:ux-agent` behind
  the same soft-dependency pattern already used for `agent-nelly:nelly-orchestrator`; add a
  `→ agent-ux (UX rendering)` section to this repo's own `INTEROP.md`.
- `agent-tdd`, `code-reviewer` (out of this repo's edit scope): would need their own equivalent
  thin delegation to adopt this. Until they do, `agent-ux` only actually serves `agent-isdd` and
  the "shared" benefit stated in Requirements is not yet realized — tracked as an Open Question.

## Data Contracts And Interfaces

- Interface: UX Event Envelope (the delegation prompt passed to `agent-ux:ux-agent`)
  - Inputs:
    - `caller`: `agent-isdd | agent-tdd | code-reviewer` — selects caller-specific rendering
      rules (e.g. TDD-stage chapter exclusion applies only when `caller = agent-tdd`).
    - `event_type`: `breadcrumb_only | phase_transition | section_checkpoint | review_threshold |
      out_of_scope_flag`
    - `phase_state`: a compact current-phase token (e.g. `Design`, `TDD:green`) — never the full
      `workflow-state.md`.
    - `delta`: the event-specific minimal payload (schema below) — never a full artifact body.
    - `artifact_path` (when applicable): a stable path for `agent-ux` to redeploy to or read
      further from on its own — caller-owned, never regenerated by `agent-ux`.
  - Outputs: breadcrumb line (always) + one line per action actually taken — unchanged from
    `ux-agent.md` today.
  - Invariants: `delta` never contains a full document body except the single confirmed section
    named in `section_checkpoint`; `agent-ux` reads `artifact_path` itself for anything beyond
    the delta, and only if it decides an action is warranted.

- Per-`event_type` delta shape:
  - `breadcrumb_only`: `{}` — `phase_state` alone is sufficient; this is the highest-frequency
    event type and must stay the cheapest.
  - `phase_transition`: `{from_phase, to_phase, feature_slug, one_line_summary}`.
  - `section_checkpoint`: `{section_name, section_body, remaining_section_names (list, names
    only, no bodies), open_gaps (list of short strings)}`.
  - `review_threshold`: `{finding_count, files_touched (list), findings: [{id, title, tier,
    severity}]}` — no evidence/diff text; `agent-ux` reads `artifact_path` for hunks itself only
    once it has decided the dashboard threshold is met.
  - `out_of_scope_flag`: `{title, file_path, context_summary}` — unchanged from today, already
    minimal.

## States, Flows, And Edge-Case Handling

- Primary flow:
  - Caller reaches a checkpoint → constructs the minimal envelope for that `event_type` →
    delegates to `agent-ux:ux-agent` → agent renders/redeploys/marks as gated → returns lines →
    caller relays verbatim (never addresses the user directly, unchanged from today).
- Edge case — `agent-ux` unavailable:
  - Caller catches the missing-plugin condition, logs one plain notice for the session (not per
    event), and continues without blocking — mirrors `agent-nelly`'s documented unavailability
    handling.
- Edge case — rapid sibling handoff in one session:
  - The `caller` field flips as ownership transfers; `agent-ux` treats each envelope
    independently and does not need session-level handoff state, since breadcrumb rendering is
    stateless per call by design.
- Edge case — contract misuse (full artifact passed instead of delta):
  - `agent-ux` checks `delta` against the expected shape for `event_type` and, if oversized,
    truncates and reports the mismatch in one line rather than rendering the full payload.

## Validation Strategy

- Unit: none — this is a prompt-defined agent, not code; no code-level unit tests apply.
- Integration:
  - Manual walkthrough per caller: drive `agent-isdd` through a full
    Requirements→Design→Tasks→handoff cycle using `agent-ux:ux-agent` in place of the in-process
    agent; confirm output lines match the current baseline shape exactly.
  - Recorded example envelopes per `event_type` (mirroring `references/example-feature/`'s
    pattern) checked into `agent-ux`'s own repo, so schema drift is visible in review.
- Manual:
  - Token-cost comparison for 3 representative events (`phase_transition`, `section_checkpoint`,
    `review_threshold`): measure prompt tokens under today's in-process call versus the new
    cross-plugin envelope. This is the acceptance gate for the "equal or smaller" success
    criterion, not an optional nice-to-have.

## Risks And Tradeoffs

- Risk: cross-plugin tool-round-trip overhead could outweigh the shared-definition savings for
  high-frequency, low-value events (`breadcrumb_only` especially, since it fires often and does
  the least work).
  - Mitigation: keep `breadcrumb_only`'s envelope to `phase_state` alone and benchmark it
    specifically as the worst case, not just the aggregate.
- Risk: three independent callers drift on what "checkpoint" means over time, quietly
  reintroducing bespoke per-plugin logic and defeating the point of the extraction.
  - Mitigation: the `event_type` enum in `agent-ux`'s `INTEROP.md` is the single source of truth;
    caller-specific nuance (e.g. TDD-stage exclusion) is a rule keyed by the `caller` field inside
    `agent-ux`'s own prompt, never a fork living in each caller's skill.
- Risk: each caller now needs its own soft-dependency fallback section, multiplying the
  maintenance the `agent-nelly` pattern already requires once per plugin.
  - Mitigation: define the fallback contract once in `agent-ux`'s `INTEROP.md`; each caller's own
    `INTEROP.md` references it by name instead of restating it (as this design's Architecture
    section already assumes for `agent-isdd`).

## Improvement Opportunities & Blast Radius

### Blast Radius

Touches `agent-isdd`'s `agents/ux-agent.md` (removed), `references/ux-conventions.md` (removed or
reduced to a pointer), every calling skill that currently invokes `ux-agent` directly, and this
repo's own `INTEROP.md` (new section). Cross-repo: `agent-tdd` and `code-reviewer` are unaffected
until and unless their maintainers separately adopt the shared agent — until then the "consistent
UX across siblings" benefit is only realized for `agent-isdd` itself.

### Security Findings (blocking)

- [ ] None identified.

### Refactor & Reduction Opportunities (non-blocking)

- [ ] Once extracted, delete `agent-isdd`'s local `ux-agent.md`/`ux-conventions.md` outright
      rather than keeping a fallback fork — two divergent implementations is a worse outcome than
      the soft-dependency gap while `agent-ux` is unavailable.

### Best-Practice Notes (non-blocking)

- [ ] Keep `agent-ux:ux-agent` pinned to `haiku` unless a specific caller demonstrates a
      rendering decision that genuinely needs stronger reasoning — nothing in today's guardrails
      suggests one does.
